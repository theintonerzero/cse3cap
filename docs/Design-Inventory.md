# Design inventory: Figma prototype to build

This is the record of every frame in the team's Figma prototype and what the build did with
it. Each row names a frame by its node ID, says which route or component it became, and
cites the file or decision that shows why. It is a record, not a spec: where this document,
the Figma file and the code disagree, the code wins and this document is the bug. The
designs themselves stay out of git, so a row points at a frame rather than embedding it.
Refresh it with the `/design-inventory` skill, which reads the file live and compares it
with the snapshot in `.claude/skills/design-inventory/frames-snapshot.md`.

## Status key

| Status     | Means                                                                               |
| ---------- | ----------------------------------------------------------------------------------- |
| `built`    | The screen exists and does what the frame shows                                     |
| `changed`  | The screen exists, but a user would notice a difference. The row says what and why  |
| `dropped`  | In the diary module's scope in the design, and not built. The row cites what cut it |
| `host app` | Shows Alumable's own platform, not the diary module, so nothing was due             |

`host app` is not `dropped`. The team scoped ten diary screens, not Alumable's home, earn,
learn or gigs pages (`docs/superpowers/plans/2026-09-14-cap-8-gig-detail.md`, "Re-shaped
to the frame"). Several host frames carry a Reflection Diary card as the way in; the build's
way in is the app's root route instead.

Roles: the design's "Employer" is the schema's `employer`, and its "Educator" is `supervisor`
(ADR #17). The build adds `assessor`, which has no column of its own.
